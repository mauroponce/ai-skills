# Code Simplification

Load when working code has demonstrated maintenance friction or a proposed architecture adds layers. Trace a representative change through the code and tests. Look for pass-through layers, duplicated Rails behavior, unnecessary metaprogramming/dependencies, needless conditionals, and tests that mirror wrappers rather than behavior. Preserve boundaries that own a transaction, workflow, integration contract, reusable query semantics, or meaningful policy. Recommend the smallest reversible simplification whose removed cognitive/change cost exceeds its migration and regression risk. A large class or service object alone is not evidence.
