# DEV negative-relevance evals

Inspect which references the agent actually loads and what its answer discusses. It should activate only expertise that can change this task's decision, while still elevating an adjacent severe issue discovered from evidence.

| Case | Expected behavior |
| --- | --- |
| Static copy change in Rails view | Loads relevant view/testing guidance only; no DB, concurrency, or generic security lecture; low execution tier. |
| React-only presentation issue | No PostgreSQL/MySQL playbook unless an actual API/data path is implicated. |
| Focused Rails query audit | Rails and detected DB guidance; no broad architecture/sustainability analysis without pressure. |
| Routine release without schema change | Verifies revision/checks/health and states no migrations; no elaborate migration sequence. |
| Framework behavior changes with version | Detects installed version, checks local/official authoritative source where needed, states source; no remembered API claim. |
