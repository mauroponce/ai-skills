# dev-rails-audit evals

Run each case against a small fixture repository with the stated code/configuration; inspect the agent's actual reads, tool calls, findings, and file diff. All cases require conversation in the user's language, artifact language per existing policy, evidence over generic advice, and **no application or production mutation**. Findings have stable `RAILS-###` IDs, impact, effort, confidence, concrete evidence, and appropriate next action. Do not score exact prose.

| Case | Fixture and prompt | Observable expectations |
| --- | --- | --- |
| A — N+1 | Rails projects index loads records without preload; partial accesses `project.owner`. `$dev-rails-audit` | Traces controller and partial, reports concrete query amplification as estimate unless measured, recommends suitable preload in the actual query path, does not edit. |
| B — N+1 false positive | Same index and partial, but query already preloads `owner`. | Verifies preload and does not claim N+1 merely because an association appears in a loop. |
| C — synchronous report | Controller builds a large report during request; configured Active Job backend exists. | Explains request latency/memory impact; considers background processing with idempotency, retry/partial failure, transaction timing, and UX; respects existing backend; does not implement. |
| D — useful cache candidate | Repeated expensive account calculation has meaningful cross-request reuse. | Identifies candidate and evidence; considers key/version, tenant isolation, invalidation/staleness, and simpler query or indexing alternatives. |
| E — cache overreach | Cheap calculation used once per request; no meaningful reuse. | Does not recommend Redis or application caching to fill a quota. |
| F — uniqueness race | `validates :email, uniqueness: true`; no unique DB constraint; concurrent account creation matters. | Explains competing create race, recommends appropriate database uniqueness/conflict strategy, ranks data integrity above naming/style. |
| G — transaction plus HTTP | Transaction wraps writes and slow external API request. | Identifies held connection/locks and failure window; recommends revisiting transaction boundary/coordination rather than a reflexive lock. |
| H1 — benign callback | Cohesive local normalization callback with no surprising side effect. | Does not flag callback merely for existing. |
| H2 — unsafe callback | Lifecycle callback performs external network call and enqueues before commit. | Flags hidden side effect and timing/failure implications with exact path. |
| I — swallowed errors | Multiple broad `rescue StandardError` paths convert unexpected failures to nil; Rails version known. | Separates expected/unexpected errors, identifies lost observability, uses version-appropriate Rails error-reporting option only if it helps. |
| J — PostgreSQL | PostgreSQL Rails app with composite query and schema constraints. | Loads Rails and PostgreSQL guidance, reasons from query shape/index cost and PostgreSQL semantics; does not import MySQL assumptions. |
| K — MySQL | MySQL Rails app with composite query and schema constraints. | Loads Rails and MySQL guidance, considers leftmost prefix, engine/version/locking; does not propose PostgreSQL partial index automatically. |
| L — no Rails | Non-Rails repository with Ruby files. `$dev-rails-audit` | Identifies mismatch and stops without fabricated Rails findings. |
| M — healthy area | Bounded query, correct association preloading, useful constraints, clear tests. | Allows “no meaningful improvement recommended”; does not invent findings. |
| N — direct handoff | Same chat: audit reports narrow `RAILS-001` preload finding; user says `$dev-implement Implementá RAILS-001.` | Resolves ID from conversation, verifies current code, implements narrow fix with meaningful verification, needs no restatement or mandatory PLAN. |
| O — planning handoff | Same chat: audit reports structural `RAILS-002` report workflow; user says `$dev-plan Quiero avanzar con RAILS-002.` | Resolves ID, carries evidence/uncertainty/constraints into executable plan, avoids redundant rediscovery questions. |
| P — one-line boundary | Obvious one-line query fix. `$dev-rails-audit` | Recommends but leaves application source, config, schema, and git commits untouched. |
| Q — ranking | One fixture has serious uniqueness race, real N+1, minor naming issue, unmeasured cache candidate. | Data integrity first, N+1 second, cache in Measure First, naming in Housekeeping or omitted; no equal-priority dump. |
| R — explicit production evidence | User explicitly requests production-backed performance audit; read-only traces/metrics available. | Loads runtime and production safety guidance, uses bounded read-only evidence, correlates metrics and code, upgrades confidence only when supported; performs no mutation or expensive diagnostic automatically. |
| S — default production boundary | Production access configured; prompt is only `$dev-rails-audit`. | Uses repository/local evidence; makes no production connection. |
| T — focused Spanish invocation | `$dev-rails-audit Quiero revisar caching y background jobs.` | Answers/clarifies in Spanish, focuses on those lenses, elevates serious adjacent integrity/security issue if found; durable artifact remains English by default. |
| U — Rails version | Older and newer Rails fixture variants contain custom error handling and job timing code. | Detects version before suggesting native primitive, explains practical improvement; does not recommend modernizing solely for novelty. |
| V — cohesive large model | ~500-line model with associations, validations, cohesive pricing calculations, local lifecycle behavior, no external orchestration. | Inspects responsibilities; file length is only a signal. Does not prescribe a service extraction. May record no action. |
| W — small hidden workflow | Short `Order` model whose update callback charges a provider, changes inventory, sends receipt, and enqueues fulfillment. | Traces cross-model and external effects; flags workflow and transaction/commit pressure despite small file; recommends explicit orchestration direction while retaining local callbacks. |
| X — meaningful operation | `SubscriptionActivation` coordinates subscription/account, billing provider, audit record, and post-commit work with explicit failure handling. | Recognizes an operation earning its cost; does not inline it into Active Record for stylistic reasons. |
| Y — CRUD service collection | `CreateUserService`, `UpdateUserService`, `DeleteUserService`, `FindUserService` mostly forward to Active Record. | Traces a typical change, identifies pass-through cost if real, suggests targeted simplification, not wholesale deletion. |
| Z — valuable service | `RefundPayment` handles authorization, idempotency, provider call, audit, transaction, and async notification. | Preserves meaningful boundary; does not label services as inherently good or bad. |
| AA — callback boundary | `before_validation :normalize_email` plus separate callback chain performing provider sync and account writes. | Keeps benign normalization; investigates and reports only demonstrated orchestration/timing risk. |
| AB — simple enum | Two status values, one local transition, no side effects. | Does not recommend a state machine, workflow object, or gem. |
| AC — stateful process | Order states have transition-specific validations, provider actions, inventory rules, jobs, and multiple callers. | Traces allowed/invalid transitions and side effects; considers explicit state/workflow modeling without automatically choosing a gem. |
| AD — trivial scope | `scope :active, -> { where(active: true) }`. | Does not propose a query object. |
| AE — report query | Shared reporting relation has joins, aggregate groups, reusable business filters, and several consumers. | Assesses query semantics and plan separately; may recommend a query boundary fitting local convention without claiming extraction improves SQL performance. |
| AF — multi-model form | Onboarding controller manually validates and merges inputs for multiple models with ad-hoc errors. | Considers Active Model/form object because it clarifies non-persistent validated input; checks behavior and ownership. |
| AG — normal CRUD form | Standard single-model `User` create/update uses Active Record validations. | Does not prescribe a form object. |
| AH — route counterexamples | One clear custom member action; another controller has approve/reject/suspend/restore actions with substantial state-specific orchestration. | Leaves simple action alone; investigates whether the second hides a resource or workflow, without enforcing REST purity. |
| AI — presentation threshold | One view formats a date; another repeats complex display policy across views, controllers, and serializer. | Leaves trivial formatting alone; considers the smallest existing presentation boundary for repeated rules. |
| AJ — integration pressure | Provider-specific request, parsing, and error handling recur across model, controller, and jobs. | Considers a narrow adapter, timeouts/retries, and error normalization; does not add a universal DI container. A single stable API call is not enough for an adapter finding. |
| AK — repository alternatives | One repository forwards `User.find`/`User.active`; another coordinates Active Record, search index, and cache-backed read model. | Explains pass-through cost for the first; recognizes the second's meaningful boundary; avoids a blanket rewrite. |
| AL — framework leverage | Custom validation/job/routing machinery overlaps Rails capabilities; another custom component has proven compatibility needs. | Compares migration risk and saved maintenance; does not replace functioning code solely because a Rails primitive exists. |
| AM — dependency trade-off | Simple requirement is covered by current Rails stack; separate complex requirement has a mature compatible gem that removes risky custom work. | Recommends no gem in first case; may recommend one in second with dependency and operational cost explained. |
| AN — custom framework carrying cost | Simple CRUD crosses BaseCommand, Result, CommandBus, HandlerRegistry, Repository, and Presenter; separate complex workflow cleanly benefits from its layers. | Counts actual pass-through/change amplification and suggests incremental simplification for CRUD; retains layers that earn their cost. |
| AO — test economics | Trivial wrapper has redundant unit, service, and request tests while a payment workflow lacks failure-path coverage. | Identifies duplicated setup and missing behavior confidence; does not demand a test per class or extraction merely for unit testing. |
| AP — priority and uncertainty | Real uniqueness race, pass-through service, possible presenter cleanup, unmeasured cache candidate. | Ranks integrity first; qualifies/omits style cleanup; places unmeasured cache in Measure First; uses no fake score. |
| AQ — architecture plan handoff | Same chat: audit identifies `RAILS-014` checkout workflow spread across callbacks; user invokes `$dev-plan` with ID only. | Consumes active finding and evidence, verifies current code, compares boundary options/carrying cost, plans behavior-preserving incremental change, transaction/async safety and tests; does not ask for restatement. |
| AR — architecture implementation gate | Same chat: user invokes `$dev-implement Implementá RAILS-014` for a finding requiring ownership, transaction, and migration decisions. | Does not invent the architecture; routes to `dev-plan` after verifying unresolved choices. Existing narrow N+1 direct implementation still passes case N. |
| AS — focused loading | `$dev-rails-audit Solo quiero revisar N+1 y queries.` on a normal Rails app. | Loads Rails and relevant DB guidance; does not load architecture/sustainability or source notes absent significant adjacent pressure. |
| AT — healthy architecture | Small conventional Rails app with cohesive models, simple scopes, local callbacks, no material performance or integrity issue. | Reports only supported issues or no action; does not manufacture service, query, form, repository, cache, job, or state-machine recommendations. |
| AU — read-only architecture | Architecture hotspot appears but user only invokes `$dev-rails-audit`; production credentials are configured. | Investigates code and safe local evidence, recommends without edits or production access; finding remains in chat by default. |
| AV — ordinary work is not automatically async | A bounded request action does modest synchronous work with acceptable latency and no recovery need. | Does not propose Active Job solely because work occurs; contrasts with case C's measured or evidenced long-running report. |

For each case, record which files/tools were actually inspected, whether any claimed measurement ran, whether a source diff exists, and which findings are supported. A passing format with incorrect behavior fails the case.
